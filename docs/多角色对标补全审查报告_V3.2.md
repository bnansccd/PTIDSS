## 2. 本轮新增修复（回归缺陷 + 部署脚本）

### 2.1 IntelService.buildRoleUserMap SQL 缺陷（p2 性能优化引入，已修复）

- **现象**：`POST /intel/push-rules/execute` 返回 400「数据校验失败」，30s 定时推送全部失败；日志报 `invalid input syntax for type json, Expected end of input, but found ","`。
- **根因**：推送目标用户查询 `role_ids @> ANY (ARRAY['[1],[2],...']::jsonb[])` 整串被 PG 当作单元素解析——每个 jsonb 数组元素必须单独引号。
- **修复**：`Collectors.joining("','", "'", "'")` 逐元素加引号，语义等价且无注入风险（值来自 sys_role.id 受控 Long）。
- **验证**：execute 恢复 200，定时推送回归正常（verify §4 推送性能断言 <3s）。

### 2.2 init_db.sh 双模式幂等三态（已修复）

- **问题**：原脚本声称「全部幂等可重复执行」，但 01 号 schema 61 个 CREATE TABLE 均无 IF NOT EXISTS，对已初始化库重放必然报错；且 [1/3] 超级用户密码与 [2/3] 角色密码共用同一 PGPASSWORD，云库场景（超级用户密码 ≠ 角色密码）第二阶段连接失败。
- **修复**：
  - **[2/3] 前切换 PGPASSWORD 为角色密码**（[1/3] 以超级用户建库，两处密码不同时正确切换）；
  - **三态幂等检测**（`to_regclass` 探测 sys_config + 18 号性能索引 ix_intel_news_source_time）：
    - 完整初始化（两者齐全）→ 跳过 DDL 重放，保留数据；
    - 部分初始化（表在索引缺）→ 补执行 17/18 号增量（均幂等）；
    - 全新库 → 01~18 全量执行。

### 2.3 start.sh JDK21 自动探测（已修复）

- **问题**：jar 由 Java 21 编译（class 65.0），系统默认 java 为 17 时启动即 `UnsupportedClassVersionError`。
- **修复**：优先 JAVA_HOME → PATH 中 21+ → 常见路径探测（`~/.tools`、`~/workspace/.tools`、sdkman、`/usr/lib/jvm`、`/usr/local`、`/opt`），找不到给出明确报错退出。

### 2.4 17 号 DDL ON CONFLICT 缺陷（已修复）

- **问题**：`ON CONFLICT (config_key)` 无法匹配**部分唯一索引**（`uk_sys_config_key ... WHERE NOT deleted`），全新库执行 17 号报 `there is no unique or exclusion constraint matching the ON CONFLICT specification`。
- **修复**：改为 `ON CONFLICT (config_key) WHERE NOT deleted DO NOTHING`（与部分索引 arbiter 匹配），全新库/补执行均幂等安全。
