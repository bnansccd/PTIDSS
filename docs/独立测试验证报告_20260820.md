## 七、发现的问题与处置

### 7.1 契约-实现偏差（4 项，均非阻断，建议下一版本修订）

1. **POST /auth/refresh 契约存在、后端 404 未实现**——JWT 有效期 120min（refresh-threshold-minutes 10 自动续期），前端实际依赖 /auth/login，建议契约标注「规划中」或后端补齐；
2. **POST /admin/roles 不可用**——角色编码受 DDL CHECK 约束固定 7 类（PRD 七类角色对齐），新建任意角色返回 500，契约 SysRole schema 未声明该限制，建议契约补充枚举说明；
3. **SysRole.dataScope 契约字段后端不存在**——实体为 role_code/role_name/description/status，建议契约 schema 对齐实体；
4. **/market/** startAt/endAt 契约 `format: date-time`（ISO8601）与实现 `yyyy-MM-dd HH:mm:ss` 不一致**——前端（low-code-cms-v2-dev HomeView）实际按空格格式传参，接口可用；契约格式声明建议改为 `pattern: yyyy-MM-dd HH:mm:ss` 或统一 ISO。

### 7.2 测试过程说明（非系统缺陷）

- 测试脚本曾对 sys_role id=1（trader）执行权限全量写回时误用「前 5 个」导致 trader 权限短暂缺失，已按种子数据恢复（9 项权限），并修正脚本为全量写回（幂等）；**最终轮次运行后已复核数据库：trader/analyst/settlement/admin/manager/compliance/mobile 七角色权限与 07_seed_data.sql 完全一致**；
- 测试数据（临时区域/用户/权限/角色/申报单/流程实例等）均已按用例自身清理逻辑删除；重复登录/审计日志为正常留痕。

## 八、结论

1. **功能验证**：开发基线 V1.6（V1.6.1~V1.6.6）登记的全部 5 域 20 接口及此前 15 域接口经独立全量测试 113/113 通过，与 PRD 23 项 FR 追溯闭环，**P0 需求实现完整可用**；
2. **契约合规**：93 个契约 path×method 全部实测（86 直接覆盖 + 7 项偏差/专项处理），4 项偏差均为文档级问题，无阻断性缺陷；
3. **权限安全**：七类角色权限门禁矩阵 7 项负向/正向用例全部符合预期，未带 token 14001、越权 14003 严格生效；
4. **交付态**：测试完成后 captcha.enabled=true 已恢复，后端以交付态重启，验证码生成/拦截链路复测通过，**系统处于可交付状态**。

**验收建议**：同意按开发基线 V1.6.6 收口；4 项契约偏差随下一版本（V1.7）修订 openapi.yaml 并登记修订记录。
