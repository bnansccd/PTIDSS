# PTIDSS 产品化配置能力交付报告 V2.3

- **批次**：task-31e（V2.2 延续）
- **日期**：2026-08-22
- **任务**：针对客户 6 项**操作友好性**诉求的最后一轮落地——① 全系统时间日期输入可选；② 业务单据关联字段输入部分内容即可搜索选择；③ 复杂参数/JSON 对接配置图形化（只输 URL/账户/密码等必要对象值）；④ 算法文件上传自动解析（保留专业操作）；⑤ 修复政策中心无法选择上传政策文件；⑥ 情报源台账"编辑对接"改弹窗图形化配置（保留 JSON 高级模式）。
- **需求基线**：客户 6 项诉求（本报告 §2 逐条对照）+ V2.2 平台配置化基线

---

## 1. 结论（一句话）

**系统操作友好性完成最后一公里**：所有时间/日期输入口统一为 `datetime-local` 选择器（后端 5 种格式宽松解析，新旧数据零迁移）；业务单据关联字段（策略/复核人/下发用户等）支持输入关键字即搜即选；复杂对接配置（情报源/数据源）由"JSON 手写"升级为**图形表单 + JSON 高级模式并存**（URL/账户/密码等必要字段表单化，敏感字段加密沿用 V2.2）；算法注册支持**上传专业算法文件系统自动解析回填**（类目猜测 + 参数模板提取 + 说明生成）；政策中心修复上传缺陷并新增**文件落盘 + 下载**；情报源台账编辑改为**弹窗图形化编辑**。回归验证 **305/305 用例全绿**（平台化 117 + 全量 177 + V2.3 新接口 11），后端编译 0 错误、前端 vue-tsc + vite build 通过，交付态 captcha=true 已恢复。

## 2. 客户 6 项诉求 → 落地对照

| # | 诉求（客户原话） | 落地 | 验证 |
|---|---|---|---|
| 1 | 系统中所有关时间日期输入口，都实现时间日期可选 | 7 个业务视图（Forecast/Trade/Decision/Optimize/Market/Review/Policy）全部时间日期输入改为 `datetime-local` 选择器（含日期+时间可选）；后端 7 处 `@DateTimeFormat` 改为 `pattern="yyyy-MM-dd" + fallbackPatterns（T 分隔/空格分隔）`，并新增 `DateUtils.parseLenient`（5 种格式宽松解析）统一处理字符串日期入参 | ✅ V2.3 脚本 3 用例：`2026-08-21T14:30`（datetime-local）→ /forecast/results 200；`2026-08-21 14:30:00`（空格）→ /trade/rolling-plans 200；`2026-08-01`（纯日期）→ /review/reports 200 |
| 2 | 涉及业务单据或其它需要填写其它业务逻辑输出的结果，都要求关联对应的数据实现输入部分内容搜索可选 | DecisionView（策略选择）、ReviewView（复核人）等关联字段改为 **datalist 搜索可选**：输入部分内容即在下拉候选中过滤，可键盘选择；候选数据来自真实业务接口（getStrategies/getAdminUsers 等），无需手抄编码 | ✅ vue-tsc + vite build 通过；关联字段候选加载与回显实测正常 |
| 3 | 可配置/编辑对接涉及复杂参数及 JSON 的技术难度，优化为只输入 URL、账户、密码等必要对象值即可完成配置 | 新增前端组件 **ConnConfigEditor**（连接参数图形编辑器）：按连接方式（api/jwt/oauth2/basic/file/poll）动态渲染必要字段表单（URL/账户/密码/客户端ID/密钥等），无需手写 JSON；同时保留"JSON 高级模式"折叠编辑（双向同步），敏感字段落库加密沿用 V2.2 ConfigCryptoService | ✅ G1/G2 既有 14 用例回归通过；IntelView/DataPlatformView 编辑回读与保存实测正常 |
| 4 | 对算法等复杂过程，保留现在专业操作情况下，客户上传专业算法文件、系统自动解析 | 新增 `POST /algorithm/parse-file`（MultipartFile，admin）：按文件内容**自动识别类目**（risk/cvar/var→risk_measure、quote/offer/bid→quote_strategy、settle→settlement、review/复盘→review、optimize/milp/最优→optimize、rule/drools→rule_engine、market/senti/舆情→market_analysis，缺省 forecast）、**提取参数模板**（.json 合法对象直接作为 paramsSchema）、**生成算法说明**（文本/脚本取文件头 300 字符，二进制包给类型提示）、生成算法编码（文件名规范化）；前端 ModelView 算法弹窗新增"选择算法文件 → 自动解析回填"（类目/参数模板/说明/版本一键回填，可继续手动调整）；原手工注册保留 | ✅ V2.3 脚本 2 用例：`price_forecast_lstm.json` → algCode=PRICE-FORECAST-LSTM/category=forecast/paramsSchema 含 horizon；`mc_cvar_risk.py`（正文含 Monte Carlo CVaR）→ category=risk_measure + 说明含正文摘要 |
| 5 | 政策中心-上传新政策，没有选择新政策文件地方，不能选择上传政策文件 | **修复缺陷**：上传弹窗新增"政策文件"选择行（pdf/txt/doc/docx/md/json）；`POST /policy/upload-file`（multipart：文件 + 登记字段，admin）文件落盘本地存储（`ptidss.storage.path: ./data/ptidss`，`local://policy/{yyyyMMdd}/{uuid8}_{清洗名}`）；`GET /policy/{id}/file` 下载（Content-Disposition 中文文件名 UTF-8 编码）；列表行内"下载"按钮（fileUrl 以 local:// 开头时显示）；原 JSON 登记接口 `/policy/upload` 完全兼容保留 | ✅ V2.3 脚本 4 用例：multipart 上传成功（fileUrl=local://…）、下载内容与上传一致（%PDF- 头）、Content-Disposition 含 filename\*=UTF-8''、列表回显 fileUrl；JSON 登记兼容 1 用例 |
| 6 | 情报中心-情报源台账-编辑对接，点击功能后跳出编辑框进行编辑，保留现有 JSON 情况下图形界面配置 | IntelView 台账"编辑对接"改为**弹窗编辑**：跳出编辑框，字段化展示连接方式/URL/账户/密码/频率/启停等（ConnConfigEditor 图形化），JSON 高级模式折叠保留（双向同步），保存即时生效；PUT /intel/sources/{id} 契约不变 | ✅ G1 既有 7 用例回归通过；弹窗编辑保存/回读实测正常 |

## 3. 实施清单

### 3.1 后端（5 文件改造）

| 文件 | 说明 |
|---|---|
| common/utils/DateUtils.java | 新增 `parseLenient`（宽松解析：yyyy-MM-dd / HH:mm / HH:mm:ss / T 分隔 / 空格分隔 5 种格式） |
| forecast/controller/ForecastController.java | 1 处 @DateTimeFormat → `pattern="yyyy-MM-dd" + fallbackPatterns={T 分隔, T 含秒}` |
| trade/controller/TradeController.java | 4 处 @DateTimeFormat 同上改造（rolling-plans/results 等时间窗口参数） |
| review/controller/ReviewController.java | 2 处 @DateTimeFormat 同上改造（复盘报告周期参数） |
| policy/service/PolicyService.java + PolicyController.java | 新增 `uploadFile`（校验→落盘 `policy/{yyyyMMdd}/{uuid8}_{清洗名}`→复用登记校验，失败清理孤儿文件）、`readFile`（local:// 读取返回 byte[]+文件名）、`sanitizeFilename`；`POST /policy/upload-file` + `GET /policy/{id}/file`；yml 新增 `ptidss.storage.path: ./data/ptidss` |
| model/service/AlgorithmService.java + AlgorithmController.java | 新增 `parseAlgorithmFile`（文件名→algCode/algName；内容→类目猜测/参数模板/说明/版本）、`guessCategory`（正文关键字→8 类目映射）、`firstLines`（压缩空白截断）；`POST /algorithm/parse-file` |

> 注：本批同时修复两处历史隐患——pom.xml 为 maven-compiler-plugin 显式声明 `annotationProcessorPaths`（lombok 1.18.28，解决 in-process javac 下 Lombok 处理器不运行问题）；7 处 @DateTimeFormat 由错误的数组用法改为标准 `pattern + fallbackPatterns`。

## 5. 遗留建议

| 项 | 说明 | 建议 |
|---|---|---|
| 政策文件存量迁移 | 存量 policy_document.fileUrl 为 minio:// 模拟地址，无实际文件；V2.3 起新上传文件落盘本地并可下载 | 生产接入对象存储时，将 local:// 文件批量迁移至 MinIO，fileUrl 前缀切换即可（下载接口按前缀分流） |
| 本地存储目录 | `ptidss.storage.path: ./data/ptidss` 为相对路径，随启动目录变化 | 生产部署改为绝对路径并纳入备份策略 |
| 算法自动解析边界 | 类目猜测为关键字规则，.jar/.zip 二进制包无法提取参数模板 | 后续可扩展"算法包规范"（jar 内 manifest 或同包 params.json 约定）实现全自动 |
