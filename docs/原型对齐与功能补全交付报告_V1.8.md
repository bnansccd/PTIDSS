## 二、任务 2：权限核查与功能补齐

### 2.1 核查结论：权限赋予正常，问题在功能缺失
- **7 角色权限矩阵与种子数据一致**（admin 全量；trader/analyst/settlement/manager/compliance/mobile 按职责分配），admin 测试残留权限已在上批次清理；
- **menu:data / menu:intel / menu:policy / menu:forecast / menu:message 等 15 个菜单权限码均存在**；
- 缺失的是**对比原型的功能**：数据底座/情报/政策三个域没有"新建增/上传/采集"写 API 与 UI。

### 2.2 后端补写 API（3 个，全部实测通过）

| 端点 | 方法 | 说明 | 权限 |
|---|---|---|---|
| `/data/sources` | POST | 新增数据源（编码唯一；类型/同步模式/状态枚举校验；connect_config 缺省 {}） | admin |
| `/intel/sources` | POST | 新增情报源（类型 6 枚举/采集方式 3 枚举校验） | admin |
| `/policy/upload` | POST | 上传政策（分类 3 枚举/状态 3 枚举/日期解析；fileUrl 模拟 MinIO） | admin |

### 2.3 权限收紧（本轮发现并修复的问题）
回归测试发现 **trader01 因拥有 menu:intel/menu:policy（mobile/trader 角色附带），可直接调用新增情报源/上传政策等写 API**——写操作权限过宽。已修复：

- `DataController`：POST /sources、POST /collect-tasks → `@RequiresRoles("admin")`
- `IntelController`：POST /sources、POST /push-rules、POST /push-rules/execute → `@RequiresRoles("admin")`
- `PolicyController`：POST /upload → `@RequiresRoles("admin")`

效果：读操作保持 menu 级（各业务角色可查看），写操作仅 admin（最小权限原则）。实测 trader 调用三写 API 均被拒（14003 缺少角色：admin）。

### 2.4 前端功能补齐
- DataPlatformView：新增数据源 + 手动采集（market/weather/settlement 三任务下拉触发）
- IntelView：新增情报源 + 情报流筛选
- PolicyView：上传政策弹窗
