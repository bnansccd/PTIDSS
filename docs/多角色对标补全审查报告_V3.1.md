## 1. 角色映射说明（审查视角 ↔ 系统角色编码）

SRS 2.2 / 数据字典 10.2 / `07_seed_data.sql` 定义的**系统固定 7 角色编码**为：`trader / analyst / settlement / admin / manager / compliance / mobile`。本轮审查的 7 个视角角色与系统编码映射如下：

| 审查角色 | 系统角色编码 | 说明 |
|---|---|---|
| admin 系统管理员 | `admin` | 直接对应，全量权限 |
| manager 交易主管 | `manager` | 直接对应（审批/报表/考核） |
| trader 交易员 | `trader` | 直接对应（申报/报价/方案确认） |
| analyst 分析师 | `analyst` | 直接对应（预测/复盘/策略） |
| auditor 审计员 | `compliance`（合规专员） | 系统无独立"审计员"角色，审计留痕由 admin 域 `/admin/logs` 提供、规则/合规校验由 compliance 承担 |
| operator 运营 | `settlement`（结算员） | 系统无独立"运营"角色，结算核对/工单/台账由 settlement 承担 |
| viewer 只读 | `mobile`（移动端）+ 最小授权用户 | 系统无独立"只读"角色；只读视角由"仅分配读权限码的用户"体现（admin 可创建） |

> **核查结论**：SRS/数据字典定义与审查要求存在 3 个角色名差异（auditor/operator/viewer 无直接角色码），属**审查视角映射**而非缺陷；但"无独立只读角色"已在遗留项中记录（见 §7 GAP-08）。

## 2. 端点-权限矩阵核查（任务 1）

### 2.1 方法

- 枚举全部 26 个 Controller 的端点（路径 + HTTP 方法 + 类级/方法级 `@RequiresPermissions` / `@RequiresRoles`），共 **149 个端点映射**（含类级 `@RequestMapping` 展开）；
- 与 `07_seed_data.sql` 权限码矩阵（17 个权限码：15 menu + 2 api + 1 data）比对；
- 特别核查：**写操作**（POST/PUT/DELETE）是否具备足够权限控制（管理/敏感类操作应 `@RequiresRoles("admin")`，与 Data/Intel/Flow/Policy/Report/Assessment/Algorithm/LlmModel 域既有收紧模式对齐）。

## 9. 结论

1. **权限面**：V2.0 之后新增的智能体/算法包/配置中心/交易网关等"管理/敏感"写端点存在仅菜单级权限控制的越权链，本轮全部收紧为 `@RequiresRoles("admin")`（9 个端点组），与既有域一致；业务类写端点权限矩阵核验无误。
2. **前端面**：路由/菜单/权限映射三方一致、无失效 API 引用；发现并修复 V2.4 多省落地后的 2 处前端硬编码遗漏（区域兜底池、结算口径）。
3. **需求面**：PRD 23/25 已实现、SRS 37/37 + FR-DM-08 已实现；仅 3 项 P1 部分实现（合同转让/省间现货/小程序）延续遗留。
4. **数据面**：实体- DDL-种子三方一致；analyst 权限矩阵职责缺口已由代码幂等补种兜底。
5. **验证**：后端 `mvn compile` 与前端 `vue-tsc --noEmit` 均通过（EXIT=0）。
