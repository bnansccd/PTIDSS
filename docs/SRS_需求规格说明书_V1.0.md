## 1. 引言

### 1.1 目的
本文档定义电力交易智能辅助决策系统的**功能需求、非功能需求、接口需求与数据需求**，作为系统设计、开发实现、测试验收的**需求基线**。所有需求条目具有唯一编号，可在 8. 追溯矩阵中定位到 PRD 条款与开发基线的模块设计、测试用例。

### 1.2 范围
- **建设目标（G1-G5）**：预测更准、决策更优、执行更稳、复盘更透、合规更严；
- **业务闭环**：政策/数据 → 预测 → 决策（多智能体）→ 申报执行 → 出清结算 → 复盘回流；
- **平台载体**：Web（Vue3）+ 微信小程序（uni-app）双端；17+1 个微服务 + 算法双栈；
- **不在范围**：交易中心出清引擎、电力市场交易系统本身的建设（仅做数据对接）；OCR 之外的其他票据识别；移动端原生 App（采用小程序）。

### 1.3 术语与缩略语
沿用开发基线《术语与缩略语表》（25 项），本文档仅补充：

| 术语 | 说明 |
|---|---|
| 会话（Session） | 一次决策任务的完整执行单元（决策编排发起至人审完成） |
| 依据链（Evidence Chain） | 决策全过程的输入、中间结果、冲突仲裁、输出全量快照，可回溯 |
| 三层归因 | 偏差按预测层 / 决策层 / 执行层进行收益影响拆解 |
| 情景模拟 | 对电价波动设定基准/保守/激进三种情景测算策略表现 |

### 1.4 参考文档
PRD v1.1；开发基线 V1.2；数据字典 V1.0；OpenAPI 契约 V1.0；前端原型 V1.0；《电力现货市场基本规则（试行）》等政策依据（见 PRD §2）。

### 1.5 需求编号规则
`FR-{组}-{序号}`：PD=政策与数据管理；TR=预测；DM=决策与优化；PL=交易申报；ST=结算；RS=复盘与策略回流；AS=成效考核；RP=报表；INT=平台与集成。优先级标注（P0/P1）与基线 2.1 追溯总表一致。

## 2. 总体描述

### 2.1 产品定位
面向发电企业交易团队的**智能辅助决策平台**：以"预测大模型 + 多智能体编排 + 联合优化 + 可解释人机协同"四位一体能力，覆盖"政策研判 → 数据采集 → 预测 → 决策 → 申报 → 结算 → 复盘 → 考核"全链路，输出**可解释、可回溯、可复核**的交易策略建议。

### 2.2 用户角色（7 类，权限见数据字典 10.2）
| 角色 | 核心诉求（对应 PRD §4 用户角色） | 主要功能域 |
|---|---|---|
| 交易员 | 快速获得可信策略并安全落地申报 | 决策工作台/申报/持仓 |
| 交易主管 | 策略复核与团队绩效 | 双人复核/复盘/考核 |
| 结算员 | 结算数据自动核对、差异闭环 | 结算核对/OCR/工单 |
| 政策分析员 | 政策快速解析与规则联动 | 政策研判/规则库 |
| 数据分析师 | 预测模型可信、指标可评估 | 预测/误差/模型管理 |
| 系统管理员 | 用户权限与审计合规 | 系统管理/审计 |
| 移动端用户 | 随时掌握行情、接收审批任务并完成审批（紧急业务正常支撑） | 小程序（行情/消息/审批，审批可操作，不含申报） |

### 2.3 运行环境与约束
- **部署**：K8s 集群（生产 3 节点起步），国产化适配预留；开发/测试/生产三环境；
- **技术栈**：见基线 3.2（Vue3/TS/ECharts、Spring Cloud Alibaba、FastAPI+PyTorch、LangGraph、Qwen 私有化、TDengine/Doris/PostgreSQL/Redis/RocketMQ/MinIO、HiGHS）；
- **时间约束**：预测任务 ≤10min、日滚动优化 ≤5min、报价方案生成 ≤3min、接口 P95 ≤3s、可用性 ≥99.5%；
- **合规约束**：等保三级；交易数据留存 ≥5 年（敏感字段加密）；结算/申报操作全程审计留痕；
- **多省约束（评审决议）**：多省扩展为 P0 期目标，region_code 按配置化多省模型设计（支撑全国推广），交易/结算/报表按 region_code 隔离（NFR-21 升级）；
- **假设**：交易中心与营销平台提供标准数据接口（REST 与文件交换双通道均保留，配置项 `exchange.channel` 可选，REST 默认、SFTP 文件兜底）；气象数据采购到位；私有化 LLM 算力满足并发。

### 2.4 需求优先级约定
- **P0**：主流程必需，缺项不得验收（Go/No-Go 硬性）；
- **P1**：增强能力，在资源允许时实现，允许分批上线（见基线 11.5 演进路线图）。

## 3. 功能需求

### 3.1 政策与数据管理

#### FR-PD-01 政策文件管理（P0）
- **需求描述**：支持政策文件（PDF/Word）上传、元数据维护（标题/发布机构/分类/标签/版本/生效日期）、全文检索与版本管理。
- **功能详述**
  - 输入：政策文件 + 元数据（分类：national/regional/provincial；标签：现货/中长期/结算/考核/信息披露）；
  - 处理：文件上传至 MinIO；版本号递增；重复文件（同名+同发布机构+同日期）提示合并；
  - 输出：政策列表（多维筛选）、详情页（原文预览 + 附件）。
- **业务规则**
  - R1 同一政策多版本按 version_no 递增，仅最新版本可被解析；
  - R2 发布机构、生效日期必填；生效日期晚于当前日期标记"未生效"。
- **异常与降级**：文件格式不支持 → 拒绝并提示支持格式；MinIO 异常 → 任务重试 3 次后标记失败。
- **验收要点**：上传/检索/筛选/版本管理用例全部通过；并发上传 20 文件无丢失（P95 ≤3s）。
- **追溯**：PRD §7.1｜基线 4.1｜原型 policy-detail.html｜API `POST /policy/parse`、`GET /policy/list`｜数据字典 5.1

#### FR-PD-02 政策智能解析（P0）
- **需求描述**：基于私有化 LLM 将政策原文解析为结构化条款（trade_rule / price_mechanism / assessment / settlement），生成规则变更候选并给出置信度。
- **功能详述**
  - 输入：政策文档（最新版本）；
  - 处理：LLM 抽取条款 → 结构化（条款类型/原文摘录/参数化字段/置信度）→ 与现有规则比对 → 生成"规则变更候选"（新增/修改/失效）→ 低置信度标记人工确认；
  - 输出：条款列表（置信度、确认状态）、规则候选清单。
- **业务规则**
  - R1 平均解析置信度 ≥0.85（PRD 指标），低于阈值的条款强制人工确认后方可入库；
  - R2 规则候选仅可"待生效"登记，须政策分析员确认 + 主管复核后激活（关联 FR-PD-03）；
  - R3 解析全程记录 LLM 输入输出快照，支持重解析（reparse）。
- **异常与降级**：LLM 服务不可用 → 降级为人工录入模式并告警；解析超时 → 异步任务重试。
- **验收要点**：抽取字段准确率、置信度分布、规则比对正确性；人工确认流程闭环（对应 9.6 测试矩阵政策行）。
- **追溯**：PRD §7.2｜基线 4.2｜API `POST /policy/parse`｜数据字典 5.2/5.4

#### FR-PD-03 政策影响研判（P1）
- **需求描述**：对已确认的政策变化点生成影响研判（变化点/影响环节/影响程度/量化测算），输出研判简报（PDF/Word）。
- **功能详述**：分析员选择变化点 → 系统关联历史数据测算影响（如费率调整对偏差考核费用的影响）→ 生成简报 → 主管确认 → 推送消息。
- **业务规则**：影响程度 high 的研判须主管确认；简报模板版本化（关联 FR-RP-02）。
- **验收要点**：简报生成、测算口径与数据字典一致、推送与消息中心集成。
- **追溯**：PRD §7.3｜基线 4.2｜数据字典 5.3

#### FR-PD-04 数据源与采集任务管理（P0）
- **需求描述**：统一管理外部数据源（交易中心/营销平台/气象/情报），支持定时/手动采集、失败重试与告警。
- **功能详述**：数据源注册（类型/连接配置脱敏存储/同步模式）→ 采集任务编排（cron）→ 采集执行 → 结果对账（记录数/时间戳）→ 异常告警。
- **业务规则**
  - R1 密钥不落明文（AES-GCM 加密存储）；连接配置变更须审批；
  - R2 采集失败自动重试 3 次（指数退避），仍失败则告警并写 collect_task.error_log；
  - R3 关键采集（现货价格/出清结果）成功率为 99.5% 可用性指标的一部分（见 4.2）。
- **验收要点**：5 类数据源接入、断点续采、对账差异告警。
- **追溯**：PRD §8.x｜基线 4.6｜API `GET /data/sources`、`POST /data/collect-tasks`｜数据字典 11.1/11.2

#### FR-PD-05 数据质量与血缘管理（P1）
- **需求描述**：数据质量规则（完整率/准确率/及时率）自动巡检、质量报告、字段级血缘追踪。
- **功能详述**：规则配置（目标表/字段/条件/阈值）→ 定时巡检 → 质量报告 → 异常通知数据组；血缘节点（表/任务/报表/模型）可视化。
- **验收要点**：三大质量指标报表、血缘图查询（API `GET /data/lineage`）。
- **追溯**：PRD §8.3｜基线 4.6｜数据字典 11.3/11.4

### 3.2 预测模块（AI 底座）

#### FR-TR-01 现货电价预测（P0）
- **需求描述**：基于预测大模型输出未来 1-7 日 96 点电价预测（日前/实时、省内/省间），含 90% 置信区间与峰谷方向判定。
- **功能详述**
  - 输入：历史价格、负荷、新能源出力、气象、供需、检修、日历特征；
  - 处理：特征工程 → 模型推理（PyTorch 时序大模型）→ 置信区间校准（分位数）→ 峰谷方向判定；
  - 输出：96 点预测值 + 上下界 + 置信度 + 峰谷时段标记。
- **业务规则（指标验收，对应 PRD §10）**
  - R1 MAPE ≤15%（全时段）；峰/谷方向准确率 ≥90%；
  - R2 置信区间校准：90% 区间实际覆盖率 85%-95%；
  - R3 训练/评估使用锁定测试集（防过拟合规范，见基线第六部分 A8）；
  - R4 特征缺失时按降级策略（规则兜底 + 结果标记 degraded）。
- **异常与降级**：模型推理超时/失败 → 规则兜底（历史相似日加权）并标记；数据不完整 → 拒绝任务并明示缺失项。
- **验收要点**：指标验收矩阵（基线 6.3）全项通过；极端行情样本（RE-05）参与评估。
- **追溯**：PRD §7.4、§10.1｜基线 4.3、第六部分 A1｜API `POST /forecast/tasks`、`GET /forecast/results`｜数据字典 6.2

#### FR-TR-02 负荷预测（P0）
- **需求描述**：区域/厂站负荷预测（96 点），MAPE ≤3%，支撑现货申报与偏差管理。
- **功能详述**：输入历史负荷+气象+日历 → 模型推理 → 输出预测值与置信区间；支持滚动修正（实时前 3 小时实际值回填修正）。
- **业务规则**：MAPE ≤3%；修正后结果保留原版本便于对比。
- **验收要点**：负荷预测用例、滚动修正效果对比。
- **追溯**：PRD §7.4、§10.2｜基线 4.3｜数据字典 2.4

#### FR-TR-03 新能源出力预测（P0）
- **需求描述**：风电/光伏分电源类型出力预测（96 点），支撑供需分析与午间低电价规避。
- **功能详述**：接入气象（辐照/风速）+ 历史出力 → 分类型模型推理 → 输出预测与置信区间；聚合展示渗透率。
- **业务规则**：渗透率变化自动生成行情预警消息（关联 FR-INT-02 消息中心）。
- **验收要点**：分类型 MAPE 达标、极端天气样本表现（RE-05）。
- **追溯**：PRD §7.4｜基线 4.3｜数据字典 2.2

#### FR-TR-04 预测任务与调度（P0）
- **需求描述**：统一的任务中心：创建预测任务（模型/日期/市场/区域）、异步执行、状态跟踪、失败重试与降级标记。
- **功能详述**：任务创建（幂等：同日同模型同市场去重）→ 排队（Redis 队列）→ 执行（算法服务）→ 结果入库（TDengine + 元数据）→ 状态回调（WebSocket 推送前端）。
- **业务规则**
  - R1 日滚动预测自动任务：每日 05:00 前完成日前预测（指标：预测 ≤10min）；
  - R2 任务耗时超预算（10min）自动告警；连续失败 3 次触发降级流程；
  - R3 所有预测结果带 model_version 与 input_version，支持版本对比。
- **异常与降级**：算法服务不可用 → 任务挂起重试；数据不完整 → 拒绝任务并返回缺失项清单。
- **验收要点**：任务生命周期用例、并发 50 任务压测（P95 ≤3s 接口响应）、幂等与去重。
- **追溯**：PRD §7.4｜基线 4.3、3.10 容量预算｜API `POST /forecast/tasks`、`GET /forecast/tasks/{taskId}`｜数据字典 6.1

#### FR-TR-05 模型版本与评估管理（P0）
- **需求描述**：模型注册（编码/版本/框架/权重/状态）、训练触发（日增量/周全量）、锁定测试集评估、上线与回滚。
- **功能详述**：训练任务（MLflow 追踪）→ 评估（锁定测试集 v2026-07 等）→ 指标不达标拒绝上线 → 一键回滚上一稳定版本。
- **业务规则**
  - R1 新版本上线须评估通过（指标矩阵见基线 6.3）且灰度观察 ≥3 日；
  - R2 在线模型与评估记录全量留痕，回滚操作审计记录；
  - R3 测试集锁定：任何模型训练/评估不得改动锁定测试集（防过拟合规范）。
- **验收要点**：训练/评估/上线/回滚全流程用例；模型指标对比视图。
- **追溯**：PRD §10｜基线 4.3、第六部分 A7/A8｜API `GET /forecast/models`、`POST /forecast/models/train`、`POST /model/evaluate`｜数据字典 6.3/6.4

#### FR-TR-06 预测结果可视化与置信区间（P0）
- **需求描述**：预测总览（96 点曲线 + 90% 置信区间 + 事后实际回填对比 + 分时段误差分析）。
- **功能详述**：按预测类型/日期/市场查询 → ECharts 渲染（预测值/上下界阴影/实际值）→ 分时段（峰/平/谷）误差表 → 模型信息卡。
- **业务规则**：实际值回填后自动更新误差指标；降级结果以角标标识。
- **验收要点**：图表渲染性能（96 点 × 多序列 ≤2s）、指标口径一致。
- **追溯**：PRD §7.4、§9.3 界面｜基线 4.7｜原型 forecast-overview.html

### 3.3 决策与优化模块（AI 底座核心）

#### FR-DM-01 决策会话与编排（P0）
- **需求描述**：以"会话"为单位发起决策任务（日滚动/现货报价/联合优化），由 LangGraph 编排多智能体顺序执行，全程状态可见。
- **功能详述**
  - 发起：选择会话类型/目标日/情景（基线/保守/激进）/参与智能体；
  - 编排：数据就绪检查 → 市场情报 → 电价预测 → 持仓合规 → 报价策略 → 风险评估 → 规则校验 → 综合决策；
  - 输出：会话状态机（orchestrating → generated → reviewed → confirmed/rejected）、阶段进度实时推送。
- **业务规则**
  - R1 编排超时预算：日滚动 ≤5min、报价方案 ≤3min（PRD 指标）；超时进入降级路径（跳过非关键智能体并标记）；
  - R2 会话全量快照（输入/输出/版本）持久化，作为依据链载体（FR-DM-06）；
  - R3 同日同类型会话可重复发起（对比多个方案），但仅一个可确认生效。
- **异常与降级**：单智能体失败 → 编排器降级（跳过并标记、人工介入可补跑）。
- **验收要点**：三种会话类型全流程用例；超时降级演练；并发 20 会话稳定性。
- **追溯**：PRD §7.5｜基线 4.4、3.9 调用链｜API `POST /decision/sessions`、`GET /decision/sessions/{sessionId}`｜数据字典 7.3

#### FR-DM-02 多智能体协同与冲突仲裁（P0）
- **需求描述**：七大智能体（情报/预测/报价/持仓合规/风险/规则/综合）协同产出候选策略；冲突时按仲裁规则解决并留痕。
- **功能详述**：各智能体输入输出契约化（agent_registry）→ 运行记录（agent_run：输入快照/输出/置信度/耗时）→ 冲突检测（如报价策略 vs 合规上限）→ 仲裁（规则优先序：合规 > 风险 > 收益）→ 仲裁记录写入会话。
- **业务规则**
  - R1 仲裁优先级：合规校验 > 风险约束（CVaR）> 期望收益；
  - R2 仲裁结果须展示给交易员（可见、可追溯），不得静默取舍；
  - R3 智能体输出置信度 <0.7 时标注并强制人工关注。
- **验收要点**：冲突场景用例（至少 5 类）、仲裁留痕完整性、置信度标注。
- **追溯**：PRD §7.5｜基线 4.4、6.4｜数据字典 7.1/7.2

#### FR-DM-03 联合优化（滚动撮合，P0）
- **需求描述**：面向多日滚动窗口（1-7 日）的 MILP 联合优化：以期望收益最大化 + CVaR 约束为目标，联合决策中长期滚动合约与现货申报。
- **功能详述**：场景抽样（蒙特卡洛，默认 100 个，10-500 可配）→ 模型构建（HiGHS，Gurobi 兜底）→ 求解 → 结果落库（方案曲线/目标值/风险指标/求解器信息）。
- **业务规则**
  - R1 求解预算：日滚动 ≤5min；超时返回当前最优可行解并标记 suboptimal；
  - R2 CVaR(95%) 约束默认 -200,000 元（可配置）；
  - R3 约束集含：申报段数上限、价格上下限、持仓比例、机组出力/爬坡、偏差电量考核（参数来自 rule_config，政策联动 FR-PD-02）。
- **异常与降级**：求解失败 → 切换备用求解器 → 仍失败则降级为启发式方案并告警。
- **验收要点**：求解质量（目标值 gap ≤5%）、预算内完成率、约束满足率（100%）。
- **追溯**：PRD §7.5、§10.4｜基线 4.4、ADR-08 求解器抽象｜API `POST /optimize/joint-tasks`、`GET /optimize/joint-tasks/{taskId}`｜数据字典 7.4

#### FR-DM-04 现货报价方案生成（P0）
- **需求描述**：基于预测与优化结果生成日前/实时分段量价申报方案（96 点映射为申报段），输出三情景候选。
- **功能详述**：场景模拟（基准/保守/激进）→ 分段聚合（段数 ≤ 规则上限）→ 合规校验 → 三情景方案对比（预期收益/CVaR/偏差风险）→ 推荐方案标记。
- **业务规则**
  - R1 段数/限价/持仓约束实时取自 rule_config（版本化）；
  - R2 推荐方案须在风险偏好阈值内（默认保守优先于激进）；
  - R3 方案生成耗时 ≤3min（PRD 指标）。
- **验收要点**：三情景对比展示、合规校验 100% 通过、推荐逻辑用例。
- **追溯**：PRD §7.5、§10.4｜基线 4.4｜原型 workspace.html（方案对比区）｜数据字典 3.5

#### FR-DM-05 情景模拟与风险度量（P0）
- **需求描述**：对候选策略进行多情景压力测试，输出 CVaR、最大回撤、偏差考核风险等指标，支持风险偏好配置。
- **功能详述**：情景定义（基准 ±10% 波动、极端事件叠加）→ 策略重算 → 风险指标计算（CVaR(95%)、最大回撤、偏差电量期望）→ 风险雷达展示。
- **业务规则**
  - R1 风险指标口径统一（见数据字典 7.4 risk_metrics 定义）；
  - R2 极端事件情景样本来自 RE-05 极端事件样本库。
- **验收要点**：指标计算正确性（与独立计算脚本对照）、情景组合用例。
- **追溯**：PRD §7.5、§10.4｜基线 4.4、6.5 竞品借鉴（GridBeyond 风险度量）

#### FR-DM-06 依据链与可解释性（P0）
- **需求描述**：决策全过程依据链：数据版本、模型版本、智能体输入输出、冲突仲裁、参数快照全量留存，支持一键回溯与导出。
- **功能详述**：会话执行中实时追加依据节点 → 依据链视图（时间线/环节/输入输出摘要/数据版本）→ 导出 JSON。
- **业务规则**
  - R1 依据链只读、不可篡改（审计保护），导出带 traceId；
  - R2 前端默认展示摘要级依据，可下钻至字段级快照。
- **验收要点**：依据链完整性校验（节点数与执行环节一致）、导出格式、审计留痕。
- **追溯**：PRD §7.5、§9.2｜基线 4.4、2.2 依赖｜API `GET /decision/sessions/{sessionId}/evidence`｜数据字典 7.3/7.2

#### FR-DM-07 人工干预与双人复核（P0）
- **需求描述**：交易员可确认/修改/驳回策略；修改须填写依据，超阈值修改强制双人复核；全部操作审计留痕。
- **功能详述**：确认（锁定方案转申报草稿）｜修改（逐项修改 + 修改依据必填 + 复核人）｜驳回（附原因重算）→ audit_log 记录 before/after 快照。
- **业务规则**

  - R2 已确认方案生成申报草稿（关联 FR-PL-02），禁止直接修改已提交申报单；
  - R3 双人复核通过 Flowable 流程引擎实现，超时未复核自动提醒。
- **异常与降级**：复核流程异常 → 方案保持"待复核"状态，不自动超时通过。
- **验收要点**：确认/修改/驳回三路径用例；阈值触发复核；审计日志完整。
- **追溯**：PRD §7.5、§11.2 核心流程｜基线 4.4、9.7 上线演练｜原型 workspace.html（人审操作区）｜数据字典 10.3

- **业务规则**：申诉窗口期为结果发布后 5 个工作日；重算后发布通知。
- **验收要点**：申诉全流程、重算正确性。
- **追溯**：PRD §7.9｜基线 4.5｜API `POST /assessment/appeals`、`POST /assessment/appeals/{id}/process`｜数据字典 8.6

### 3.8 报表模块

#### FR-RP-01 报表中心（P1）
- **需求描述**：模板化报表（交易/结算/预测/考核/经营），配置数据源与布局，按周期生成、导出（Excel/PDF/Word）、推送。
- **功能详述**：模板配置（数据源/布局/口径说明）→ 实例生成（定时/手动）→ 导出 → 推送（邮件/消息）。
- **业务规则**：报表口径与数据字典一致；敏感报表（结算金额）导出需授权。
- **验收要点**：模板化生成用例、口径一致性抽查、导出格式。
- **追溯**：PRD §7.10｜基线 4.5、ADR-07 报表引擎｜API `POST /report/instances`、`GET /report/instances/{id}/export`｜数据字典 9.1/9.2

#### FR-RP-02 报送格式支持（P1）
- **需求描述**：按交易中心/上级单位报送格式（Excel 模板/表头/口径说明）出表，支持格式版本管理。
- **功能详述**：报送模板导入 → 字段映射配置 → 数据填充 → 预检（缺失/口径）→ 导出。
- **验收要点**：报送格式样例逐字段核对通过。
- **追溯**：PRD §7.10｜基线 4.5｜数据字典 9.1

### 3.9 平台与集成

#### FR-INT-01 消息中心（P0）
- **需求描述**：统一消息（预测摘要/市场预警/决策待办/结算差异/考核提醒/情报推送），Web + 小程序双通道，未读提醒。
- **功能详述**：消息模板（类型/渠道/接收人规则）→ 事件触发（业务环节）→ 发送（RocketMQ → Web 站内信 + 小程序订阅消息）→ 已读管理。
- **业务规则**：市场预警 high 级实时推送（≤30s）；决策待办截止前提醒；消息留存 6 个月。
- **验收要点**：双通道送达、实时性指标、未读统计。
- **追溯**：PRD §7.11｜基线 4.5｜API `GET /message/list`、`POST /message/{id}/read`｜数据字典 10.4

#### FR-INT-02 流程引擎集成（P0）
- **需求描述**：复核/审批/申诉/工单等流程统一走 Flowable，提供流程实例追踪与待办。
- **功能详述**：流程定义（复核/审批/申诉/工单处理）→ 发起实例 → 任务分配 → 办理/转办 → 超时提醒 → 历史查询。
- **业务规则**：关键流程（双人复核/申诉/工单关闭）不可跳过节点；操作留痕。
- **验收要点**：四类流程用例、超时提醒、留痕完整性。
- **追溯**：PRD §7.11、§11.2｜基线 4.5、3.9｜API `POST /flow/start`、`GET /flow/instances/{instanceId}`

#### FR-INT-03 审计与权限（P0）
- **需求描述**：登录/关键操作全量审计；菜单/接口/数据三级权限（7 类角色）；等保三级合规支持。
- **功能详述**：审计日志（traceId/用户/动作/对象/快照/结果）→ 审计查询与导出 → 权限配置（角色-权限）→ 数据权限（区域/机组范围）。
- **业务规则**：关键操作（申报提交/方案确认/结算审核/权限变更）强制审计；审计日志不可篡改（追加式存储，按月分区）。
- **验收要点**：审计完整性（对照关键操作清单）、越权访问拦截、等保测评支撑。
- **追溯**：PRD §9.4｜基线 3.7 安全架构｜数据字典 10.2/10.3

#### FR-INT-04 情报中心（P0 正式，RE-01 评审决议升级）
- **需求描述**：多源市场情报（价格公告/天气/供需/政策/舆情）采集、归一化标签、重要度分级、按规则推送。
- **功能详述**：情报源管理（60+ 源，RE-01）→ 采集（API/爬虫/文件）→ 清洗归一化（标签/重要度）→ 推送规则（标签+重要度→角色/渠道）→ 情报流展示。
- **业务规则**：high 级情报实时推送（≤30s）；情报与决策会话联动（可一键引入情报结论）。
- **验收要点**：源接入、标签准确率、推送规则生效、与决策联动。
- **追溯**：PRD §7.11、RE-01｜基线 6.8.1、2.4｜API `GET /intel/news`、`POST /intel/push-rules`｜数据字典 11.5/11.6

### 4.2 可用性需求
| 编号 | 指标 | 目标值 | 说明 |
|---|---|---|---|
| NFR-10 | 系统可用性 | ≥99.5% | 月度统计，故障时间 ≤3.6h/月 |
| NFR-11 | RPO | ≤1 天 | 业务数据备份 |
| NFR-12 | RTO | ≤4 小时 | 故障恢复 |

### 4.3 安全需求（等保三级）
- NFR-14 认证：SSO 统一认证 + 账号密码（BCrypt）+ 验证码（连续失败触发）；连续 5 次失败锁定 30 分钟；
- NFR-15 授权：菜单/接口/数据三级权限；关键操作（申报提交/方案确认/结算审核/权限变更）强制审计；
- NFR-16 传输安全：全链路 HTTPS/TLS1.2+；敏感接口可选 mTLS；
- NFR-17 存储安全：敏感字段（价格/金额/联系方式）AES-GCM 加密；密钥托管 KMS；
- NFR-18 隐私与合规：个人数据最小化采集、脱敏展示；日志脱敏；
- NFR-19 等保三级：通过三级测评（含测评整改项）。

### 4.4 可扩展性需求
- NFR-20 微服务无状态化，支持水平扩容；预测/优化算法服务独立扩缩容；
- NFR-21 新增市场/区域（多省）扩展：数据域按 region_code 隔离，配置化接入；
- NFR-22 新增数据源/情报源：通过数据源管理配置化接入，不改代码；
- NFR-23 求解器可替换（HiGHS/Gurobi/SCIP），模型可插拔。

### 4.5 易用性需求
- NFR-24 关键流程（决策→确认→申报）步骤 ≤5 步；高频操作一键化；
- NFR-25 决策建议附依据链入口（可解释）；风险提示分级醒目；
- NFR-26 页面符合原型 V1.0 布局规范；响应式适配（Web 1920/1366、小程序 750rpx）；
- NFR-27 操作类消息（确认/失败/异常）即时反馈 ≤1s。

### 4.6 可维护性需求
- NFR-28 全链路日志（traceId 贯穿）；日志分级（debug/info/warn/error）；
- NFR-29 监控指标（Prometheus + Grafana）：服务健康/调用链/队列积压/模型指标/采集对账；
- NFR-30 配置中心统一管理，变更走发布流程；灰度发布支持。

### 4.7 合规需求
- NFR-31 交易/结算数据与操作全程留痕，满足审计抽查；
- NFR-32 关键业务参数（规则/指标/模型）版本化，支持追溯；
- NFR-33 系统时间统一北京时间；金额/电量单位规范（数据字典通用约定）。

## 5. 接口需求

### 5.1 外部接口
| 接口 | 方向 | 协议/格式 | 用途 | 关联需求 |
|---|---|---|---|---|
| 交易中心数据接口 | 双向 | HTTPS/REST + SFTP 文件双通道（配置项 `exchange.channel` 可选，REST 默认） | 行情/申报/回执/出清/结算 | FR-PD-04、FR-PL-02/04、FR-ST-01 |
| 营销平台接口 | 单向 | REST/定时同步 | 机组/合同/电量数据 | FR-PD-04 |
| 气象数据服务 | 单向 | REST/文件 | 预报数据（GFS/ECMWF/CMA） | FR-TR-02/03 |
| 微信小程序服务端 | 双向 | HTTPS/REST | 行情/消息/审批 | FR-INT-01 |
| 短信/邮件网关 | 单向 | 服务商 API | 告警/提醒（P1） | FR-INT-01 |
| 内部 LLM 推理服务 | 双向 | REST/gRPC | 政策解析/报告摘要/智能体 | FR-PD-02、FR-RS-01 |

### 5.2 内部接口
- 统一网关 `api/v1/**`，JWT 鉴权，全链路 traceId（契约见 OpenAPI V1.0）；
- 服务间调用走 RocketMQ 事件（8 主题，见基线 5.4）或同步 REST（契约内定义）；
- 算法服务双栈：Java（optimize/决策）与 Python（forecast/LLM/OCR）通过服务网关路由，异步任务经 MQ 解耦。

### 5.3 数据接口
- TDengine（st_* 时序）、Doris（分析/报表）、PostgreSQL（业务）、Redis（缓存/队列）、MinIO（文件）——表结构与字段定义见《数据字典 V1.0》。
