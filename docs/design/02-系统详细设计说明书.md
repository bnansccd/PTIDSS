## 1. 引言

### 1.1 目的

在概要设计基础上，对 PTIDSS 各模块的类结构、接口契约、业务规则、状态机、数据库访问与关键流程进行细化设计，达到"开发人员无需再作设计决策即可编码"的程度。

### 1.2 范围

覆盖后端全部 16 个业务域（22 个 Controller）与前端 15 个页面，含公共横切设计。

## 2. 总体设计

### 2.1 后端包结构

```
com.ptidss
├── agent/        智能体管理（controller/domain/mapper/service）
├── auth/         认证（controller/dto/service）
├── common/       公共（annotation/aspect/config/constant/domain/entity/exception/security/utils）
├── data/         数据管理（controller/domain/mapper/service）
├── decision/     决策（controller/domain/dto/mapper/service）
├── flow/         流程引擎
├── forecast/     预测
├── intel/        情报
├── market/       行情（controller/dto/service）
├── message/      消息
├── model/        模型管理
├── optimize/     优化
├── policy/       政策
├── report/       报表
├── review/       复盘+考核
├── settlement/   结算+OCR
├── system/       系统管理（controller/domain/impl/mapper/service）
└── trade/        交易（controller/domain/dto/mapper/service）
```

### 2.2 分层约定

| 层 | 职责 | 约束 |
|---|---|---|
| Controller | 参数校验（JSR-303）、权限注解、调用 Service、返回 Result.success() | 不写业务逻辑 |
| Service | 业务规则、状态机、事务边界（@Transactional） | 依赖 Mapper 与领域模型 |
| Mapper | MyBatis-Plus BaseMapper | 不含业务 |
| Entity/Domain | 数据库实体（@TableName/@TableId） | 与 DDL 一一对应 |

### 2.3 代码规范

- Java 8、Lombok（@Data/@Builder）、Slf4j 日志；
- 实体继承 BaseEntity（created_at/updated_at/version/deleted）；
- 雪花 ID 由 MybatisMetaObjectHandler 自动填充（insertFill/updateFill）；
- 统一使用 Result<T>（code/message/data），成功 code=0；
- 业务异常抛 ServiceException（业务码 5xx 段），权限异常 ForbiddenException（14003）。

## 3. 公共横切设计

### 3.1 统一响应与异常体系

| 组件 | 说明 |
|---|---|
| Result<T> | {code, message, data}；成功 code=0 |
| GlobalExceptionHandler | @RestControllerAdvice：参数校验 400、认证 14001、授权 14003、业务 500(业务码)、系统 500 |
| ServiceException | 业务异常，携带 code 与 message |
| ForbiddenException | 权限拒绝，code=14003（"缺少角色：xxx"或"无权限访问"） |

错误码段：
- 14001 认证失败/令牌失效；14002 令牌过期；14003 权限不足；
- 5xxx 业务码（重复编码、枚举非法、状态非法等）。

### 3.2 认证与权限切面（PreAuthorizeAspect）

- 注解：类级 `@RequiresPermissions("menu:*")`、方法级 `@RequiresRoles("admin")`；
- 逻辑：admin 角色全放行 → 角色 anyMatch 任一匹配放行 → 否则抛 ForbiddenException(14003)；
- 覆盖：全部 Controller 类级菜单权限 + 写操作方法级 admin 收紧（data/decision/flow/forecast/intel/message/model/optimize/policy/report/review/settlement/trade 写端点）。

### 3.3 审计切面（AuditAspect）

- 触发动作：confirm_plan/modify_plan/declaration_submit/declaration_create/declaration_withdraw/settlement_reconcile/settlement_ticket_process/policy_upload/policy_parse/intel_source_create/push_rule_execute/permission_change/user_create 等；
- 记录：trace_id/user_id/username/action/target_type/target_id/before_snapshot/after_snapshot/ip/user_agent/result/region_code；
- 存储：audit_log 分区表（按月），追加式不可篡改。

### 3.4 数据加密

- AES-GCM 工具（common/utils）：用于 phone/email/contract.price/settlement.total_amount 等敏感字段；
- 密钥来源：配置项注入（生产 KMS 托管演进）；
- 展示：前端脱敏展示（管理员可见明文需授权接口）。

### 3.5 区域路由（X-Region-Code）

- 前端 useRegionStore 持有当前区域，request 拦截器自动携带 `X-Region-Code` 头；
- 后端 RegionContext（ThreadLocal）解析头，缺省回退系统默认区域（CN-32）；
- 数据层双保险：RLS 策略（sys_user_region × region_code）+ 应用层查询条件 region_code；
- 结算口径联动：region.settlement_period 决定台账/报表周期口径。

### 3.6 验证码（CaptchaService）

- Kaptcha 标准实现，无万能码；验证码会话键存 Redis（或内存单机模式）；
- 配置开关 `ptidss.captcha.enabled`：true 强制校验（登录请求体 captcha/captchaId），false 跳过（测试/联调用）；
- 连续登录失败触发验证码要求。

## 4. 模块详细设计

## 4.1 认证模块（auth）

### 4.1.1 接口契约

| 方法 | 路径 | 说明 | 入参要点 |
|---|---|---|---|
| GET | /auth/captcha | 生成验证码 | — |
| POST | /auth/login | 登录 | username/password/captcha/captchaId |
| POST | /auth/logout | 登出 | — |
| POST | /auth/refresh | 刷新令牌 | refreshToken |
| GET | /auth/current | 当前用户信息 | 返回用户+角色+权限+regions |

### 4.1.2 登录流程

```
前端 ──GET /auth/captcha──► 后端（生成图片+会话键）
前端 ──POST /auth/login──► 校验验证码 → BCrypt 校验密码
      → 生成 accessToken(JWT 2h) + refreshToken(7d)
      → 更新 last_login_at → 返回 user/roles/permissions/regions
前端 ──GET /auth/current──► 恢复用户态（F5/直链）
前端 ──POST /auth/refresh──► 401 拦截器自动续期
```

### 4.1.3 业务规则

- 密码 BCrypt 哈希存储；登录响应 data.accessToken 字段承载令牌；
- refresh 使用 refreshToken 换取新 accessToken；登出仅前端清理（无状态令牌）；
- 权限快照：登录/current 返回 permissions 数组（perm_code 列表），前端 canAccess 过滤菜单。

| GET | /admin/logs、/{id} | 审计日志查询 | menu:admin |

### 4.2.2 领域模型

- SysUser：username 唯一（WHERE NOT deleted）、role_ids JSONB、org_code（机构归属）、status（active/locked/disabled）；
- SysRole：role_code 7 枚举（trader/analyst/settlement/admin/manager/compliance/mobile）；
- SysPermission：resource_type（menu/api/data）+ resource_pattern；15 个 menu:* 权限码种子；
- SysRegion：region_code（CN-32 等）+ market_support JSONB + exchange_channel（rest/sftp/both）+ settlement_period（natural_month/trading_month）+ status/launch_order；
- 关联：sys_role_permission（角色-权限多对多）、sys_user_region（用户-区域多对多）。

### 4.2.3 业务规则

- 用户-区域授权是数据权限（RLS）的来源表；机构（org_code）为组织归属展示用（如 JS-CN32→CN-32 区域匹配）；
- 角色/权限变更走审计（action=permission_change）；
- 删除为逻辑删除（deleted=true）；admin 角色不可删除自身。

## 4.6 决策模块（decision）

### 4.6.1 接口契约

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| POST | /decision/sessions | 发起决策会话（rolling/spot_quote/joint_optimize） | menu:decision |
| GET | /decision/sessions/{sessionId} | 会话详情（状态机/智能体运行） | menu:decision |
| POST | /decision/sessions/{sessionId}/confirm | 人工确认方案 | menu:decision |
| POST | /decision/sessions/{sessionId}/modify | 人工修改（需填依据+复核） | menu:decision |
| POST | /decision/sessions/{sessionId}/reject | 人工驳回（原因必填，pending/confirmed→rejected） | menu:decision |
| POST | /decision/sessions/{sessionId}/rerun | 降级补跑（pending+degraded → 重新编排补齐缺失智能体） | menu:decision |
| POST | /decision/sessions/{sessionId}/intel-reassess | 情报触发式重算（仅 pending：按最新情报流重评评分快照并留痕） | menu:decision |
| GET | /decision/sessions/{sessionId}/evidence | 依据链导出 | menu:decision |

### 4.6.2 会话状态机

```
orchestrating（编排中）
   → generated（方案已生成，待人工审阅）
      → confirmed（确认：锁定转申报草稿）
      → modified（修改：填依据，超阈值触发双人复核）
      → rejected（驳回：附原因，可重算）
```

### 4.6.3 业务规则

- 会话类型 3 枚举 + 情景 3 枚举（baseline/conservative/aggressive）；
- 编排序列（SRS FR-DM-01）：market 情报 → forecast 预测 → compliance 持仓合规 → quote 报价 → risk 风险 → settlement 结算 → review 复盘 → 综合决策（编排器最后步骤，不落 agent_run）；
- 证据链 evidence_chain JSONB 全量快照（智能体输入输出/仲裁记录/参数版本）；
- 运行留痕：每次编排逐智能体写 agent_run（run_id/输入快照/输出/置信度/推理依据/耗时/状态），按 session_no 关联；
- 修改阈值：单时段电量变动 >10% 或全时段收益变动 >5% 强制 reviewer2 双人复核；
- 智能体 7 枚举：forecast/market/quote/risk/compliance/settlement/review（agent_registry 版本化，懒种子 7 条）；
- 仲裁优先级：合规 > 风险（CVaR）> 收益；仲裁记录写入 conflict_records（合规未通过 → 按合规上限强制调整；报价 vs 风险价差 >60 元/MWh → 取均值）；
- 置信度标注：任一智能体 confidence <0.7 → strategy.attentionRequired=true + lowConfidenceAgents 清单（SRS R3 强制人工关注）；
- 超时降级：编排预算 日滚动 ≤5min / 报价方案 ≤3min；超预算跳过非关键智能体（review/settlement）并标记 degraded，可人工补跑（SRS R1）；
- 降级补跑：POST rerun 对 pending+degraded 会话重新完整编排（不模拟超时），重写 strategy/evidence_chain/conflict_records，agent_run 追加 -R 后缀记录，orchestrator_version=orchestrator-v0.2-rerun；
- 情报→决策联动：market 智能体聚合近 24h 情报流（intel_news，空窗回退最新 50 条）做舆情/供需评分 [-1,1]（关键词×重要度加权），评分经报价系数影响 forecast/quote 输出价（FR-INT-04）；会话创建时评分快照落 strategy.intel（score/window/count/impact）；
- 情报触发式重算：POST intel-reassess 仅 pending 会话可重评（重算评分快照 + note 留痕"情报变更重评"）；IntelService 推送执行含 high 重要度情报派发时自动对近 24h 待审会话批量重评（reassessPendingSessions，响应含 intelReassessed 计数，异常不阻断推送）；
- 模型接入：agent_registry.model_config.modelCode 绑定 model_registry 在线模型 → 编排调用 ModelService.inference 走模型推理（mode=model）；未绑定/模型不可用回退确定性算法（mode=mock + modelFallback 标记，推理依据注明）；
- 模型推理契约（对齐 MLflow/Flower）：inference 返回 96 点预测序列（predictionSeries，按模型编码/版本确定性生成）+ seriesStats（均值/峰/谷）+ 模型置信度 + 注册表 metrics；mode=model 时模型置信度覆盖智能体置信度，输出注明模型版本与序列摘要；
- 规则联动：compliance 智能体实时读取 rule_config active 规则（段数上限/偏差考核阈值），政策条款变化自动影响校验结果（FR-PD-01/02）。

### 4.8.2 申报单状态机

```
draft（草稿，可编辑）
 → pending_submit（待提交）
 → submitted（已提交，禁改）
 → receipted（已回执）
 → partially_matched（部分成交，配合 trade_result）
撤销重报：submitted → draft（保留历史版本 + 审计）
```

### 4.8.3 业务规则

- compliance_check JSONB 落库：段数上限/价格上下限/持仓比例/峰谷约束（参数来自 rule_config）；

#### 4.16.1 连接参数字段级加密（P2，common/utils/ConfigCryptoService）

| GET | /policy/{id}/file | 政策原文下载（仅 local:// 落盘文件） | 登录 |

- 存储：`ptidss.storage.path`（yml，默认 `./data/ptidss`）；落盘路径 `policy/{yyyyMMdd}/{uuid8}_{清洗文件名}`，fileUrl 约定 `local://policy/...`；登记复用 upload 校验（title 非空/编号生成/状态默认），校验失败清理孤儿文件；
- 文件名清洗：`/`、`\`、控制字符替换为 `_`，空名回退 policy.pdf；
- 下载：readFile 仅处理 local:// 前缀（minio:// 模拟地址或无文件返回 404）；响应 `Content-Disposition: attachment; filename*=UTF-8''{URLEncoder(name)}` + application/octet-stream；
- 前端：上传弹窗文件选择行（pdf/txt/doc/docx/md/json）；列表 fileUrl 以 local:// 开头显示"下载"按钮（blob 下载，解析 Content-Disposition 中文文件名）；原 POST /policy/upload（JSON 登记）兼容保留。

#### 4.17.6 情报源台账弹窗编辑（需求 6）

- IntelView 台账"编辑对接"由卡片内联编辑改为**弹窗编辑**：点击后跳出编辑框，ConnConfigEditor 图形化配置（连接方式/URL/账户/密码/频率/启停），JSON 高级模式折叠保留（双向同步）；
- 保存调用 PUT /intel/sources/{id}（V2.2 契约不变），保存即生效；敏感字段加密/脱敏沿用 V2.2。

## 5. 前端详细设计

### 5.1 架构分层

```
src/
├── api/        http.ts（request<T> 封装）+ 各域 api 模块 + types.ts（契约类型）
├── stores/     auth（令牌/用户/权限）、region（当前区域）
├── views/      15 个业务页面（路由懒加载）
├── layouts/    MainLayout（侧边菜单 + 顶栏 + 区域切换）
├── utils/      permission（canAccess）、format
└── router/     index.ts（路由 + 守卫）
```

### 5.2 请求封装（http.ts）

- 自动附加 Authorization: Bearer {accessToken} 与 X-Region-Code；
- 响应解包：code=0 → data；14001 → refresh 重试一次；14003 → 提示无权限；
- 网络错误 toast 提示；文件上传（multipart）专用封装。

### 5.3 路由守卫

```
登录态校验 → 用户态恢复（/auth/current + region.init）
→ canAccess(path, permissions) 菜单权限过滤 → 无权限回落 /dashboard
```

### 5.4 左侧导航分组（对齐原型 dashboard.html）

- MainLayout 菜单按原型 5 分组渲染（19 项全部保留）：总览（决策驾驶舱）/ 行情与预测（市场行情、预测中心、数据管理）/ 决策与交易（智能决策、交易申报、联合优化、智能体管理、模型平台）/ 结算与复盘（结算管理、复盘分析、成效考核、报表中心）/ 政策与系统（情报中心、政策中心、消息中心、数据底座、审批流、系统管理）；
- 分组内按 canAccess 过滤，整组无可见项不渲染分组标题；nav-group 样式（小号灰色分组标题）。

### 5.5 移动端 H5 适配（FR-PL-05 P1）

- main.css ≤768px 媒体查询：侧栏置顶横向滚动（nav-group 隐藏）、统计卡双列、网格单列、表格横向滚动（white-space: nowrap）、弹窗 92vw、表单换行；全部页面通用生效（登录/驾驶舱/消息/审批等 P1 场景先行覆盖）；
- 独立小程序工程仍留待后续排期（PRD FR-PL-05 小程序本体）。

### 5.6 状态管理

- auth store：user（含 roles/permissions/regions）、accessToken、loaded 标志；
- region store：currentRegion（默认取用户 regions[0] 或 CN-32）、切换时触发数据重载。

### 5.5 页面-组件设计约定

- 统计卡：.stat-grid 4 卡布局（对标原型 wf-stat 样式）；
- 表格：筛选条（form-row）+ 表格 + 分页 + 空态（muted）；
- 弹窗：.modal-mask 自研模态；操作反馈 .toast；
- 状态徽标：.badge（badge-green/badge-red/badge-orange/badge-blue/badge-gray）；
- 图表：ECharts 按需引入（行情/预测/复盘曲线）。

## 6. 关键流程时序设计

### 6.1 日滚动决策主流程（交易员）

```
1. 交易员 查看驾驶舱（行情速览/预测摘要/待办）
2. 创建决策会话 POST /decision/sessions {type=rolling, date, scenario}
3. 轮询会话状态 GET /decision/sessions/{id}（编排中→已生成）
4. 查看方案与依据链 GET /decision/sessions/{id}/evidence
5. 确认/修改/驳回 POST .../confirm | /modify（修改需依据，超阈值双人复核）
6. 方案转申报草稿（FR-PL-01 confirm → POST /trade/declarations）
7. 合规预检 → POST /trade/declarations/{id}/submit → 提交交易中心
8. 成交回填 GET /trade/results → 持仓更新 GET /trade/positions
9. 复盘闭环：POST /review/reports（周/月）→ 偏差归因 → 策略回流
```

### 6.2 结算核对流程（结算员）

```
1. 结算周期结束 → 结算记录同步（system/exchange 双路）
2. POST /settlement/records/{id}/reconcile 发起核对
3. 差异科目生成工单 GET /settlement/tickets
4. POST /settlement/tickets/{id}/process 处理（留痕）
5. 主管确认关闭 → 台账关账（settlement_ledger closed）
6. OCR 兜底：POST /ocr/tasks 上传结算单 → 低置信人工复核
```

### 6.3 情报推送流程

```
1. 情报采集入库 POST /intel/sources（源管理）
2. 情报流查询 GET /intel/news（重要度/类型筛选）
3. 推送规则 POST /intel/push-rules（标签×重要度→角色/渠道）
4. 执行推送 POST /intel/push-rules/execute → message_record（biz_ref 幂等）
5. 前端消息中心 GET /message/list 展示 → 已读标记
```

## 7. 非功能设计

### 7.1 性能

- 查询接口：分页必带 pageNo/pageSize；列表禁止全表；热点查询走索引（DDL 已建）；
- 时序查询：TDengine 按 region/时间窗下推；图表 96 点 × 多序列 ≤2s；
- 任务型接口（预测/优化）：异步执行 + 状态轮询，接口本身快速返回。

### 7.2 安全

- 输入校验：JSR-303 + 枚举白名单（非法值返回业务错误而非 500）；
- SQL 安全：MyBatis-Plus 参数绑定，无字符串拼接；
- 越权防护：RLS + 应用层 region 双保险；写操作 admin 角色收紧；
- 审计：关键操作全量留痕（见 3.3）。

### 7.3 可维护性

- traceId：MDC 贯穿请求（登录时生成，日志输出）；
- 日志分级：info/warn/error 分文件落盘（logs/ 目录）；
- 配置集中：application.yml + 启动参数覆盖（captcha.enabled 等）。
