## 3. 总体架构设计

### 3.1 架构原则

1. **需求-设计-接口-界面-数据五层一致**：SRS、详细设计、OpenAPI 契约、前端原型、DDL 基线版本联动，任一变更同步修订；
2. **AI 辅助决策定位**：系统输出策略建议，人机协同确认后方可执行，关键决策全链路可解释、可追溯；
3. **多省配置化**：所有业务数据按 region_code 隔离（RLS + 应用层双保险），新增省份零代码接入；
4. **算法服务双栈**：Java 承载业务与优化求解，Python 承载预测/LLM/OCR，通过服务网关路由；
5. **关键数据双通道**：交易中心对接 REST/SFTP 双通道、结算数据系统自算/交易中心双路留存。

分层存储约定：
- **原始层**：外部采集原始报文（MinIO + collect_task 对账）；
- **明细层**：行情时序（TDengine）、业务明细（PG 分区表）；
- **汇总层**：结算台账、考核结果、复盘报告、报表实例（PG）；
- **应用层**：驾驶舱指标、依据链、策略库。

### 3.7 安全架构（等保三级支撑）

1. **认证**：账号密码（BCrypt）+ Kaptcha 图形验证码；JWT 无状态令牌（accessToken + refreshToken 双令牌），登录失败连续触发验证码；
2. **授权（三级权限）**：
   - 菜单级：`menu:*` 权限码控制前端菜单与路由（canAccess 过滤）；
   - 接口级：`@RequiresPermissions("menu:*")` 类级 + `@RequiresRoles("admin")` 方法级，PreAuthorizeAspect 统一拦截（admin 全放行、anyMatch 任一匹配、拒绝抛 ForbiddenException code=14003）；
   - 数据级：region_code 列级隔离（RLS 策略 + 应用层 X-Region-Code 路由双保险）；
3. **传输**：HTTPS/TLS1.2+；**存储**：联系方式/合同价格/结算金额 AES-GCM 加密；**审计**：关键操作 audit_log 追加式存储、按月分区、前后快照；
4. **模型安全**：LLM 输入输出快照留存，规则库版本化可回滚。

### 4.2 模块职责与关键接口

#### 4.2.1 认证模块（auth）
- 职责：登录/登出/刷新令牌/当前用户/验证码；
- 关键接口：`POST /auth/login`（返回 data.accessToken，校验验证码）、`GET /auth/captcha`、`POST /auth/refresh`、`GET /auth/current`；
- 依赖：CaptchaService（Kaptcha）、JwtUtil、SysUserService。

#### 4.2.2 系统管理模块（system）
- 职责：机构（区域）/用户/角色/权限/审计日志管理；
- 关键接口：`/admin/users`（CRUD + 重置密码 + 区域授权）、`/admin/roles`（CRUD + 权限分配）、`/admin/permissions`（CRUD）、`/admin/regions`（CRUD）、`/admin/logs`（审计查询）；
- 业务规则：用户名唯一（逻辑删除过滤）、role_ids JSONB、用户-区域多对多（sys_user_region）、写操作需 admin 角色。

#### 4.2.3 政策模块（policy）
- 职责：政策文件上传/版本管理/智能解析/影响研判/规则沉淀；
- 关键接口：`GET /policy/list`、`POST /policy/upload`（admin）、`GET /policy/{id}`、`POST /policy/parse`、`GET /policy/{id}/brief`；
- 业务规则：版本号递增、分类 national/regional/provincial、解析条款置信度标注、研判影响程度分级（high 需确认）。

#### 4.2.4 数据管理模块（data）
- 职责：数据源注册、采集任务、质量报告、血缘追踪；
- 关键接口：`GET /data/sources`、`POST /data/sources`（admin）、`POST /data/collect-tasks`（admin）、`GET /data/quality/report`、`GET /data/lineage`；
- 业务规则：source_type 5 枚举、sync_mode 枚举、连接配置脱敏、失败重试。

#### 4.2.5 预测模块（forecast）+ 模型模块（model）
- 职责：预测任务生命周期（电价/负荷/新能源）、预测结果 96 点、模型注册/训练/评估；
- 关键接口：`POST /forecast/tasks`、`GET /forecast/tasks/{taskId}`、`GET /forecast/results`、`GET /forecast/models`、`POST /forecast/models/train`、`GET /model/registry`、`POST /model/inference`、`POST /model/evaluate`；
- 业务规则：同日同模型同市场幂等、降级标记 degraded、置信区间（lower/upper/confidence）、模型版本化。

#### 4.2.6 决策模块（decision）
- 职责：决策会话编排、多智能体运行、依据链、人工确认/修改/驳回；
- 关键接口：`POST /decision/sessions`、`GET /decision/sessions/{sessionId}`、`POST /decision/sessions/{sessionId}/confirm`、`/modify`、`GET /decision/sessions/{sessionId}/evidence`；
- 业务规则：会话状态机（orchestrating→generated→reviewed→confirmed/rejected）、修改必须填写依据、仲裁记录留痕。

#### 4.2.7 优化模块（optimize）
- 职责：联合优化任务（MILP 求解）、策略回测、策略库；
- 关键接口：`POST /optimize/joint-tasks`、`GET /optimize/joint-tasks/{taskId}`、`POST /optimize/backtests`、`GET /optimize/strategies`；
- 业务规则：求解器 HiGHS 默认、suboptimal 降级返回、revenue_delta 回测收益增量（验收核心）。

#### 4.2.8 交易模块（trade）
- 职责：日滚动方案、申报单、成交结果、持仓视图；
- 关键接口：`GET /trade/rolling-plans`、`POST /trade/rolling-plans/{planId}/confirm`、`GET/POST /trade/declarations`、`POST /trade/declarations/{id}/submit`、`GET /trade/results`、`GET /trade/positions`；
- 业务规则：申报状态机（draft→pending_submit→submitted→receipted→partially_matched）、合规预检 JSON 落库、position_view 合成持仓。

#### 4.2.9 结算模块（settlement）+ OCR（ocr）
- 职责：结算记录同步、核对、差异工单、台账、结算单识别；
- 关键接口：`GET /settlement/records`、`POST /settlement/records/{id}/reconcile`、`GET /settlement/tickets`、`POST /settlement/tickets/{id}/process`、`POST /ocr/tasks`、`GET /ocr/tasks`、`POST /ocr/tasks/{taskId}/review`；
- 业务规则：双路留存（system/exchange）、周期口径配置 `settlement.periodMode`、核对通过率 ≥95%、工单闭环。

#### 4.2.10 复盘考核模块（review + assessment）
- 职责：复盘报告、偏差三层归因、策略回流、考核指标/结果/申诉；
- 关键接口：`POST /review/reports`、`GET /review/reports/{id}`、`POST /review/strategy-feedback`、`GET /assessment/indicators`、`GET /assessment/results`、`POST /assessment/appeals`、`POST /assessment/appeals/{id}/process`；
- 业务规则：归因层 forecast/decision/execution、回流需主管确认、申诉窗口 5 个工作日。

#### 4.2.11 报表模块（report）
- 职责：模板管理、实例生成、导出；
- 关键接口：`GET /report/templates`、`GET /report/instances`、`POST /report/instances`、`GET /report/instances/{id}/export`；
- 业务规则：数据快照落库可追溯、敏感报表导出需授权、模板版本化。

#### 4.2.12 行情模块（market）
- 职责：现货/中长期价格、供需、热力图（时序数据访问）；
- 关键接口：`GET /market/price/spot`、`GET /market/price/midlong`、`GET /market/supply-demand`、`GET /market/heatmap`；
- 业务规则：X-Region-Code 区域路由、时间格式 `yyyy-MM-dd HH:mm:ss`、source 标记。

#### 4.2.13 情报模块（intel）
- 职责：情报流、情报源、推送规则；
- 关键接口：`GET /intel/news`、`GET/POST /intel/sources`、`GET/POST /intel/push-rules`、`POST /intel/push-rules/execute`；
- 业务规则：intel_type 6 枚举、fetch_mode 3 枚举、重要度分级、high 级实时推送 ≤30s、推送幂等（biz_ref=INTEL-{newsId}）。

#### 4.2.14 消息/流程模块（message + flow）
- 职责：站内信、流程实例；
- 关键接口：`GET /message/list`、`POST /message/{id}/read`、`POST /flow/start`、`GET /flow/instances/{instanceId}`；
- 业务规则：7 种消息类型、channel JSONB（web/miniapp）、流程状态机（running/completed/terminated）。

## 5. 关键设计决策（ADR 摘要）

| 编号 | 决策 | 理由 | 影响 |
|---|---|---|---|
| ADR-01 | 单服务（Spring Boot）承载全部业务模块 | 当前规模单体最优，部署简单，满足 P0 | 预留模块边界，微服务演进 |
| ADR-02 | JWT 无状态 + 双令牌 | 水平扩容友好、刷新免重登 | auth 域 refresh 接口 |
| ADR-03 | PostgreSQL 分区表 + RLS | 按月分区控制表膨胀；RLS 按 region 强制隔离 | declaration/trade_result/settlement_record/audit_log 分区 |
| ADR-04 | TDengine 承载时序数据 | 行情/预测高吞吐、按省子表物理分片 | market 域、forecast 结果明细 |
| ADR-05 | region_code 多省隔离（列级 + RLS + 应用路由） | 评审决议⑤多省 P0 目标 | 全部业务表含 region_code |
| ADR-06 | 结算周期双口径配置 `settlement.periodMode` | 评审决议③自然月/交易月并存 | 台账/报表口径一致 |
| ADR-07 | 求解器抽象（HiGHS/SCIP/Gurobi） | 开源默认、商业兜底，可替换 | optimize 域 solver 字段 |
| ADR-08 | 权限注解切面（@RequiresPermissions + @RequiresRoles） | 声明式权限、admin 全放行、可审计 | 全部写端点 admin 收紧 |
| ADR-09 | 轻量自研流程引擎替代 Flowable | 当前流程简单（复核/工单/申诉），避免重依赖 | flow 域，Flowable 演进预留 |
| ADR-10 | 情报推送幂等（biz_ref） | 防重复推送 | intel_news.push_status |

## 6. 部署架构

```
┌─────────────────────────── 生产环境 ───────────────────────────┐
│ Nginx (HTTPS)                                                  │
│   ├─ /ptidss/*  ──► Spring Boot (9080, context-path=/ptidss)  │
│   └─ /          ──► 前端静态资源（Vite build 产物）             │
├────────────────────────────────────────────────────────────────┤
│ PostgreSQL 18 (5432, ptidss 库)      TDengine 3.x (6030)       │
│ Redis (6379)                          MinIO (9000)             │
└────────────────────────────────────────────────────────────────┘
```

- 后端启动参数示例：`--ptidss.captcha.enabled=true --spring.datasource.password=...`；
- 验证码开关：生产态 `captcha.enabled=true`（测试可用 `--ptidss.captcha.enabled=false` 绕过）；
- 端口约定：后端 9080、前端 dev 30001、PostgreSQL 5432；
- 监控：Prometheus + Grafana（deploy/prometheus/），日志分级落盘 logs/{info,warn,error,debug}。
