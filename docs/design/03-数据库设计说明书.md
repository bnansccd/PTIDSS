## 1. 设计总则

### 1.1 数据库选型

| 库 | 用途 | 版本 | 说明 |
|---|---|---|---|
| PostgreSQL | 业务数据（交易/结算/政策/系统） | 18 | RLS 行级安全、分区表、JSONB |
| TDengine | 时序数据（行情/出力/负荷/预测/气象） | 3.x | 超级表+子表、按省分片、保留策略 |
| Redis | 令牌/验证码/队列 | 7.x | 缓存与任务队列 |
| MinIO | 文件（政策/结算单/报表/模型权重） | 最新稳定 | 对象存储 |

### 1.2 命名规范

- 表名：小写下划线；业务表按数据域前缀（sys_/trade_/settlement_/policy_/forecast_/...）；
- 字段：小写下划线；主键统一 `id BIGINT`（雪花 ID）；
- 通用审计字段：`created_at/updated_at TIMESTAMP DEFAULT now()`、`version INT`（乐观锁）、`deleted BOOLEAN DEFAULT FALSE`（逻辑删除）；
- 枚举字段统一 VARCHAR + CHECK 约束（枚举集中参照 06_enum_dict.sql，防漂移）；
- 敏感字段：`*_encrypted` 或 AES-GCM 加密存储（phone/email/price/total_amount）。

### 1.3 主键与索引约定

- 主键：雪花 ID（应用层 MybatisMetaObjectHandler 填充），避免自增主键暴露业务量；
- 唯一索引：`uk_*` + `WHERE NOT deleted`（逻辑删除兼容唯一性）；
- 普通索引：`ix_*`，遵循左前缀原则（region_code 必入索引，多省隔离检索）；
- 分区表：唯一索引必须含分区键（如 uk_declaration_no(declaration_no, trade_date)）。

## 16. RLS 行级安全（多省数据隔离）

依据《多省 region 路由与数据隔离方案 V1.2》：

1. 策略：业务表（contract/rolling_plan/declaration/trade_result/quote_plan/clearing_result/settlement_record/settlement_ledger/report_instance/forecast_result/forecast_task/intel_news 等含 region_code 的表）启用 RLS；
2. 规则：`region_code = current_setting('app.region_code')` 或用户授权区域集合（sys_user_region 关联）；
3. 应用层：登录后按 X-Region-Code 设置 `app.region_code` 会话变量（SET LOCAL），与 RLS 策略协同；
4. 双保险：应用层查询条件仍显式携带 region_code（防止误配 RLS 导致数据泄漏/不可见）；
5. 平台级数据（sys_* 管理表、全国情报 region_code IS NULL）不受 RLS 限制，由应用层权限控制。
