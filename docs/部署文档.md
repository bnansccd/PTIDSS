# PTIDSS 部署文档（V2.5）

> 适用版本：V2.5（2026-08-22 批次，含各省行情采集重试/降级、90 天长期验证脚本、算法包规范全自动适配）
> 关联文档：数据字典 V1.0｜DDL 基线 01~15｜OpenAPI V1.1 契约｜算法包规范｜V2.4市场化省份接入与长期验证方案

## 1. 环境要求

| 组件 | 版本 | 说明 |
|---|---|---|
| JDK | 8（64 位） | 后端运行环境，本仓库配套 `.tools/jdk8` |
| Maven | 3.6+ | 后端构建（配套 `.tools/apache-maven-3.8.8`） |
| Node.js | 18+ | 前端构建（`.nvmrc`） |
| PostgreSQL | 14+（基线按 18 校验） | 业务库 `ptidss`，端口 5432 |
| Nginx | 1.20+（可选） | 生产静态托管 + 反向代理（同源部署） |
| TDengine | 3.x（可选） | 行情/负荷时序库（`02_tdengine_schema.sql`，独立部署，不参与进程编排） |

## 2. 目录结构（部署相关）

```
PTIDSS/
├── ptidss-server/                 # 后端（Spring Boot 2.7.13，context-path /ptidss）
│   └── src/main/resources/
│       ├── application.yml        # 公共配置（默认 profile=dev）
│       └── application-prod.yml   # 生产配置模板（环境变量化）
├── frontend/                      # 前端（Vue3+Vite，产物 dist/）
│   └── .env.production            # 生产 API 地址（/ptidss 同源）
├── docs/ddl/                      # DDL 基线（01~15 幂等）
├── docs/算法包规范.md              # 算法包规范（jar/zip 全自动适配约定）
├── docs/V2.4市场化省份接入与长期验证方案.md  # 行情源接入与长期验证指标口径
├── tests/longrun/                 # 90 天长期验证脚本（日/周/月/季 + README）
└── deploy/

    ├── nginx/ptidss.conf.example  # Nginx 配置模板
    └── docker/                    # 容器化可选方案（docker-compose）
```

## 3. 部署步骤（进程级，主推）

### 3.1 初始化数据库

```bash
cd /home/odoo/workspace/PTIDSS/deploy
sudo ./scripts/init_db.sh          # 建库建用户 + 执行 01~15 DDL（幂等）
```

- 脚本以超级用户 `postgres` 连接（可用 `sudo -u postgres psql` 场景）；
- 全部语句幂等，可重复执行；执行完输出基线计数（角色/权限/用户/区域/情报源/算法注册/模型任务/行情源配置）；
- DDL 范围：01 基础表、03 视图、06 枚举、07 种子、10 平台配置（含算法注册表）、11 SPI 执行器、12 交易网关、13 模型任务、14 市场化区域、15 行情采集配置（V2.5）；
- `02_tdengine_schema.sql` 为时序库脚本，由 TDengine 侧单独执行（如启用行情时序落库）；
- `09_rls_policies.sql`（多租户行级安全）默认执行，生产多租户隔离必开。

### 3.2 构建

```bash
./scripts/build.sh                 # 后端 mvn package（跳过测试）+ 前端 npm build
```

产物：`ptidss-server/target/ptidss-server-1.0.0.jar`、`frontend/dist/`。

### 3.3 启动后端（生产态）

```bash
export TOKEN_SECRET=$(openssl rand -hex 32)   # 生产必改：令牌签名密钥
export DB_PASSWORD='<生产数据库密码>'
./scripts/start.sh                 # java -jar --spring.profiles.active=prod，端口 9080
./scripts/status.sh                # 状态检查（进程/端口/库连通/前端产物）
```

- 验证码默认开启（`CAPTCHA_ENABLED=true`）；登录页出现图形验证码即冒烟通过；
- 初始账号 `admin / Ptidss@2026` 仅对 `PLACEHOLDER:APP_INIT` 占位用户首次启动生效，首登后请立即改密；
- 全部可覆盖配置见 `application-prod.yml`（DB_*/TOKEN_*/CAPTCHA_ENABLED/INIT_DEFAULT_PASSWORD）。

### 3.4 Nginx（静态托管 + 反代）

```bash
sudo cp deploy/nginx/ptidss.conf.example /etc/nginx/conf.d/ptidss.conf
sudo mkdir -p /opt/ptidss && sudo cp -r frontend/dist /opt/ptidss/frontend/
sudo nginx -t && sudo systemctl reload nginx
```

- 前端与后端**同源**（`VITE_API_BASE=/ptidss`），无跨域；
- 访问入口：`http://<host>/`（前端）、`http://<host>/ptidss/`（API）；
- 对外域名变化时仅需调整 `server_name` 与前端构建变量，无需改后端。

### 3.5 停止 / 重启

```bash
./scripts/stop.sh                  # 优雅停止（15s 超时强杀）
./scripts/start.sh                 # 重启
```

## 4. 一键部署包（公有云/迁移）

```bash
cd PTIDSS
./deploy/scripts/build.sh          # 产出 jar 与 dist
./deploy/scripts/package.sh        # 产出 dist/ptidss-deploy-v2.5.tar.gz
```

- 部署包保持仓库相对布局（ptidss-server/target、frontend/dist、docs/ddl、deploy、tests/longrun），脚本路径假设全部成立；
- 目标机器：`tar xzf` → `./deploy/scripts/init_db.sh` → `./deploy/scripts/start.sh` → `./deploy/scripts/status.sh`；
- 部署包内含 90 天验证脚本（tests/longrun）与关键文档，上线即具备验证能力。

## 5. 容器化部署（可选）

```bash
cd PTIDSS
./deploy/scripts/build.sh                       # 先产出 jar 与 dist
cd deploy/docker
export DB_PASSWORD='<生产数据库密码>'
docker compose up -d --build
```

三服务：`postgres:18`（首次启动自动执行 docs/ddl 01~15 初始化脚本）→ `ptidss-server`（healthcheck 依赖）→ `nginx`（静态 + 反代）。数据持久化于 named volume `pgdata`。

## 6. 上线后动作（V2.5 新增）

### 6.1 切换真实行情（各省交易中心地址 + 重试/降级）

- 默认全部市场化源 `conn_config.mock=true`（确定性模拟），生产接入真实行情：
  - 将台账中各省源 `conn_config.endpoint` 配置为交易中心公开地址（山东/山西/甘肃/广东/蒙西等，见 DDL 15 与《V2.4市场化省份接入与长期验证方案》§3）；
  - `conn_config.mock` 置 `false`，按需调整 `timeoutMs`/`retries`/`frequencyMinutes`；
- 系统自动执行链路：HTTP 拉取 → 指数退避重试（1s/2s/4s）→ fallbackUrl 降级 → 状态留痕（lastSuccessAt/lastError/consecutiveFailures，连续失败 ≥10 次自动停用并告警日志）；
- 观测：`GET /intel/fetch-status`（健康台账）、`POST /intel/fetch`（admin 手动触发）。

### 6.2 90 天长期验证（日/周/月/季）

```bash
cd /opt/ptidss/tests/longrun
python3 daily_validation.py --exit-code        # 每日（未达标退出码 1，可联动告警）
python3 weekly_validation.py                   # 每周
python3 monthly_validation.py                  # 每月（模型 MAPE/方向准确率/对标）
python3 quarterly_validation.py                # 每季
```

- crontab 示例与指标口径见 `tests/longrun/README.md`；报告留存 `reports/`；
- 依赖 `python3 + requests`；生产验证码开启时配置专用账号或经内网访问。

### 6.3 算法包规范（jar/zip 全自动适配）

- 客户算法包内置 `ptidss-algorithm.json`（name/category/version/description/params）或 MANIFEST `PTIDSS-Algorithm-*` 属性，上传 `POST /algorithm/parse-file` 即自动回填注册要素；
- 优先级：ptidss-algorithm.json > MANIFEST 自定义属性 > 启发式解析（V2.4 兼容）；详见 `docs/算法包规范.md`。

## 8. 常见问题

| 现象 | 处置 |
|---|---|
| 登录页无验证码 / 验证码接口 404 | `ptidss.captcha.enabled` 未生效：确认启动 profile 为 prod 且未用旧 jar；改配置后需重启 |
| 数据库连接失败 `Connection refused` | 确认 PG 监听 5432、`DB_*` 环境变量正确；`init_db.sh` 已建库建用户 |
| 登录后 F5 刷新跳到登录页 | 检查前端版本（已接入用户态恢复）；检查 `VITE_API_BASE` 与后端可达性 |
| 令牌过期被踢（14001 循环） | 已接入 `/auth/refresh` 滑动续期（剩余 <10min 自动续）；确认 `TOKEN_SECRET` 前后一致（更换密钥会使存量令牌全部失效） |
| 前端页面 500 / 白屏 | 前端为 dev 直连时检查 vite dev server；生产检查 dist 是否最新构建（`npm run build`） |
| 定时采集/推送不执行 | 确认启动日志无 `@EnableScheduling` 异常；`collect_task.cron_expr` 为 5/6 段 cron；情报推送需 `intel_push_rule.status='active'` 且情报 `tags` 与规则 `tags_filter` 有交集 |
| 行情源持续失败 | `GET /intel/fetch-status` 查看 lastError/consecutiveFailures；确认 endpoint 可达、mock 开关；连续 ≥10 次自动停用需手动改回 enabled |
| 长期验证脚本 FAIL | 按 `tests/longrun/README.md` 指标口径核对（失败率分母为 enabled 源、月验证读任务详情接口）；连续 FAIL 按《方案》§5 处置 |
| 端口冲突 | `start.sh [PORT]` 指定端口；前端 dev 端口见 `vite --port` |
| 时序数据（st_*）无入库 | 时序库为 TDengine 独立部署（02 脚本），PG 库不含时序表；数据对接见《数据对接文档》 |

## 9. 版本与回滚

- 后端：`ptidss-server/target/` 保留历史 jar，回滚 = 替换 jar 后重启；
- 前端：`frontend/dist` 保留历史构建目录，nginx `root` 指向回滚目录即可；
- 数据库：DDL 全部幂等且带版本注释（v1.0.1/v1.0.2/v2.x），升级增量在 `docs/ddl` 按序执行（已包含 01~15）；重大变更建议先 `pg_dump` 备份。
